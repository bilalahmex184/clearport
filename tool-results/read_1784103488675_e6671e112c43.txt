     3→     3→     3→## Project Goal
     4→     4→     4→Transform the audited ClearPort prototype (single-page AI Studio demo) into a production-ready SaaS product with:
     5→     5→     5→- Supabase backend (Postgres + Storage + 11 Edge Functions in TypeScript/Deno)
     6→     6→     6→- Real document ingestion pipeline (upload → Gemini two-pass extraction → schema validation → math/cross-field validation → confidence flagging → exception routing → CSV export)
     7→     7→     7→- Frontend UI/UX remains the same (dark-mode enterprise dashboard, 7 pages)
     8→     8→     8→- Target: < 1 minute from upload to structured, cross-validated output
     9→     9→     9→
    10→    10→    10→## Architecture Decisions
    11→    11→    11→- **Auth**: Supabase anonymous auth (auto sign-in on page load) — preserves the no-login UX while enabling proper RLS with `auth.uid()`. Users can later link an email/password.
    12→    12→    12→- **RLS**: All tables scoped by `user_id UUID REFERENCES auth.users(id)`. Storage objects scoped by `{user_id}/` path prefix.
    13→    13→    13→- **Edge Functions**: 11 functions, all JWT-verified (`verify_jwt = true`). Service-role key used internally for storage + Gemini calls.
    14→    14→    14→- **Gemini**: `@google/genai` in edge functions (Deno runtime). `GEMINI_API_KEY` set as Supabase secret.
    15→    15→    15→- **Frontend**: Next.js 16 App Router, single `/` route, `framer-motion` (not `motion`), shadcn/ui available, `@/` path alias.
    16→    16→    16→- **Fallback mode**: If edge functions not deployed, frontend falls back to simulated data with a "Demo Mode" indicator.
    17→    17→    17→
    18→    18→    18→## 11 Edge Functions
    19→    19→    19→1. `upload-document` — secure file upload to Storage + create `documents` row
    20→    20→    20→2. `extract-document` — first-pass Gemini extraction (OCR + structured field extraction)
    21→    21→    21→3. `cross-validate` — second-pass Gemini cross-document validation
    22→    22→    22→4. `schema-validate` — JSON schema validation of extracted fields
    23→    23→    23→5. `math-validate` — math/cross-field validation (weights, totals, HTS consistency)
    24→    24→    24→6. `flag-exceptions` — confidence-threshold-based exception flagging
    25→    25→    25→7. `get-shipments` — fetch shipments with fields + exceptions (joined)
    26→    26→    26→8. `update-exception` — resolve single exception (accept/correct/reject)
    27→    27→    27→9. `batch-accept` — batch-accept high-confidence exceptions
    28→    28→    28→10. `export-csv` — CSV export of shipment audit data
    29→    29→    29→11. `get-document-url` — generate signed URLs for document viewing

    81→    81→    81→- Function 8 (update-exception): validates status ∈ {Accepted, Corrected, Rejected}; requires correctedValue when status='Corrected'. Pushes a new ExceptionHistoryEntry onto the front of the history array (per spec: oldValue = newValue = correctedValue || extractedValue). Updates exception (status, resolved_at, resolved_by, history, corrected_value when Corrected). Syncs the linked document_field (is_flagged=false, reviewer_action=status, corrected_value when Corrected). Recomputes shipment.current_confidence as initial_confidence + round((resolved/total) * 30), capped at 100; if no exceptions remain unresolved, flips shipment.status to 'Approved'.     82→    82→    82→- Function 9 (batch-accept): resolves threshold as body.threshold > operational_rules.invoice_threshold > 80 (default). Recomputes shipment confidence + status using the same formula as update-exception. Audit log message: "Batch action: Approved N high-confidence exceptions (>= X%) in SHIP-ID". Returns `{ success: true, acceptedCount, shipmentStatus, threshold }`.
    83→    83→    83→- Function 10 (export-csv): builds a CSV with a metadata header block (Shipment ID, Shipper, Consignee, Status, Created At, Exported At/By), then a Fields section (Field Key,Field Label,Value,Source Document,Confidence,Flagged,Status), blank line, then an Exceptions section (Exception ID,Field Name,Reason,Confidence,Status,Resolved By).
