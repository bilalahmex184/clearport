     1→# ClearPort Production Rebuild — Worklog
     2→
     3→## Project Goal
     4→Transform the audited ClearPort prototype (single-page AI Studio demo) into a production-ready SaaS product with:
     5→- Supabase backend (Postgres + Storage + 11 Edge Functions in TypeScript/Deno)
     6→- Real document ingestion pipeline (upload → Gemini two-pass extraction → schema validation → math/cross-field validation → confidence flagging → exception routing → CSV export)
     7→- Frontend UI/UX remains the same (dark-mode enterprise dashboard, 7 pages)
     8→- Target: < 1 minute from upload to structured, cross-validated output
     9→
    10→## Architecture Decisions
    11→- **Auth**: Supabase anonymous auth (auto sign-in on page load) — preserves the no-login UX while enabling proper RLS with `auth.uid()`. Users can later link an email/password.
    12→- **RLS**: All tables scoped by `user_id UUID REFERENCES auth.users(id)`. Storage objects scoped by `{user_id}/` path prefix.
    13→- **Edge Functions**: 11 functions, all JWT-verified (`verify_jwt = true`). Service-role key used internally for storage + Gemini calls.
    14→- **Gemini**: `@google/genai` in edge functions (Deno runtime). `GEMINI_API_KEY` set as Supabase secret.
    15→- **Frontend**: Next.js 16 App Router, single `/` route, `framer-motion` (not `motion`), shadcn/ui available, `@/` path alias.
    16→- **Fallback mode**: If edge functions not deployed, frontend falls back to simulated data with a "Demo Mode" indicator.
    17→
    18→## 11 Edge Functions
    19→1. `upload-document` — secure file upload to Storage + create `documents` row
    20→2. `extract-document` — first-pass Gemini extraction (OCR + structured field extraction)
    21→3. `cross-validate` — second-pass Gemini cross-document validation
    22→4. `schema-validate` — JSON schema validation of extracted fields
    23→5. `math-validate` — math/cross-field validation (weights, totals, HTS consistency)
    24→6. `flag-exceptions` — confidence-threshold-based exception flagging
    25→7. `get-shipments` — fetch shipments with fields + exceptions (joined)
    26→8. `update-exception` — resolve single exception (accept/correct/reject)
    27→9. `batch-accept` — batch-accept high-confidence exceptions
    28→10. `export-csv` — CSV export of shipment audit data
    29→11. `get-document-url` — generate signed URLs for document viewing

Recomputes shipment confidence + status using the same formula as update-exception. Audit log message: "Batch action: Approved N high-confidence exceptions (>= X%) in SHIP-ID". Properly escapes values per RFC 4180 (wrap in double quotes when value contains comma/quote/newline/CR; double inner quotes). Uses CRLF line endings for Excel compatibility. Writes audit_log entry. Returns `{ success: true, csv, filename: "ClearPort_Audit_<SHIP-ID>.csv" }`.
    84→- Function 11 (get-document-url): accepts either `{ storagePath }` or `{ documentId }`.
